# AGENTS.md — Snowflake_Moodys_MarketContext

Synthetic Moody's Investors Service / Moody's Analytics-style credit-rating + market-context dataset for the Cumulus FSC demo. **Plan 13 is the FINAL Cumulus plan in the rollout (13 of 13).** **Business-account-scoped with daily cadence** — one row per business account (`V_ACCOUNT_ANCHORS WHERE ACCOUNT_TYPE_FLAG = 'BUSINESS'`) per `PROFILE_DATE`, the second daily-cadence plan after Plan 7 (WorldCheck AML). The source of truth is `procedures/sp_create_procedure.sql` (generated from `procedures/sp_generate_moodys_market_context.py` by `scripts/deploy_sp.py`); every fact below was checked against it and the live table on 2026-11-09.

> **History.** Plan 13 was first built **instrument-scoped**: one row per `INSTRUMENT_UNIVERSE` ticker (2,004), keyed `(TICKER, PROFILE_DATE)`, seeded by ticker, rating biased by `SECTOR`, market cap from `BASE_PRICE × shares`, not joinable to Account. The v2 schema (`schemas/moodys_market_context_v2.sql`) re-scoped it to business accounts so every commercial profile gets a credit / market-context tile. None of the instrument design is live: no `TICKER` column, no `INSTRUMENT_UNIVERSE` read, no `_SECTOR_RATING_BIAS`.

> **v1.x multi-org (Phase A, 2026-05-29 `c9119d32`; checked against live 2026-11-09).** Live table: PK `RECORD_ID` (`UUID_STRING()` default, the row id); UNIQUE `(ACCOUNT_ID, PROFILE_DATE)` (`RELY = false`, not enforced, no `ORG_ID`, which is cosmetic); `ORG_ID VARCHAR(18)` nullable, `DEFAULT 'JDO'`, added near the end of the column list (not first). The row factory stamps `"ORG_ID": anchor.get("ORG_ID", "JDO")` from the business-account anchor, and the MERGE source SELECT, `ON` and `INSERT` carry it. **OUTLOOK_LAST_CHANGED_DATE defensive casts preserved**: `pd.to_datetime(df[col])` on the Pandas side and `TO_DATE(TO_TIMESTAMP_NTZ(col / 1e9))` in the MERGE source SELECT (the all-NULL date mistype guard from commit `64812af`). The deployed MERGE `ON` is `ORG_ID, ACCOUNT_ID, PROFILE_DATE`, and that is what keeps rows unique; UPDATE SET skips `ORG_ID`. Multi-org rollout runbook: `Snowflake_Cumulus_Common/docs/ROLLOUT.md` (A6).

> **Outlook moves (2026-10-24).** `RATING_OUTLOOK` / `OUTLOOK_LAST_CHANGED_DATE` are no longer purely year-stable:
> `_apply_outlook_moves` overlays deterministic Stable -> Negative/Watch -> Stable episodes (salt `moodys_moves`, fixed
> 180-day slots with a per-account phase, 10%/slot — 50%/slot for owners with < 500 business accounts via
> `OWNER_BOOK_SQL` — slots from 2025-09-01, `001am` ids with a Stable baseline only).
> The rest of this file's "year-stable outlook" wording describes the *baseline*. Don't re-anchor the move seeds to
> the year or add a lookback window — either breaks the "every change is dated, dates never move silently" history
> contract pinned by `tests/test_moodys_outlook_moves.py`. The staging `write_pandas` target is
> `DATA_JEDAIS.FINS__PUBLIC` (the old `FINS.PUBLIC` target failed 21 runs Jul-Aug 2026). See README "Outlook moves".

## Boundaries
- Owns: `DATA_JEDAIS.FINS__PUBLIC.MOODYS_MARKET_CONTEXT`, `SP_GENERATE_MOODYS_MARKET_CONTEXT(NUM_DAYS INT DEFAULT 1)`, `TASK_DAILY_MOODYS_MARKET_CONTEXT`, the staging table `MOODYS_MARKET_CONTEXT_STAGING`, and the DC Data Stream / DLO / DMO (`BT_Moodys_Market_Context__dlm`) that federates this table.
- Does NOT own: `V_ACCOUNT_ANCHORS`, the seed/coverage helpers — see `Snowflake_Cumulus_Common`. Does not own the inbound `FINSDC3_DATASHARE` Account share that `OWNER_BOOK_SQL` reads.
- Does NOT own any outbound Snowflake share. DC reads through via the existing "Snowflake (Federate / Zero Copy)" connector.
- **Account-scoped** — rows are keyed by `(ORG_ID, ACCOUNT_ID, PROFILE_DATE)` (MERGE `ON`; table PK is `RECORD_ID`), one per business account per day. `ACCOUNT_ID` joins `ssot__Account__dlm.ssot__Id__c`; the DMO carries that relationship (`account_id__c` → `ssot__Id__c`, N:1).

## Conventions
- **Inputs.** `_rows_for(anchor, profile_date)` reads only `ACCOUNT_ID`, `ACCOUNT_TYPE_FLAG`, `INDUSTRY`, `ANNUAL_REVENUE`, `EMPLOYEE_COUNT` (plus `ORG_ID`, and `OWNER_BOOK_SIZE` that `main` attaches from `OWNER_BOOK_SQL`). Missing `INDUSTRY` → `"Other"`; missing `ANNUAL_REVENUE` → $5M for the valuation math (but `ANNUAL_REVENUE_USD` stays NULL).
- The SP uses `cumulus_common.seed_for(...)` for determinism with **two salts** (plus `moodys_moves` for outlook moves):
  - **`moodys`** (day-bucketed via `_daily_seed(account_id, run_ts)`) — drives the daily market signals `DAILY_VOLATILITY_PCT` and `THIRTY_DAY_PRICE_CHANGE_PCT` (and through the latter, `MARKET_CAP_USD`'s daily drift). Both draw from one per-row `random.Random(daily_seed)` in that order.
  - **`moodys_year`** (year-bucketed via `_year_seed(account_id, run_ts, suffix)` → `datetime(run_ts.year, 1, 1)`) — drives the year-stable editorial fields `CREDIT_RATING`, baseline `RATING_OUTLOOK`, baseline `OUTLOOK_LAST_CHANGED_DATE`, `FIFTY_TWO_WEEK_HIGH_USD`, `FIFTY_TWO_WEEK_LOW_USD`, `RATING_AGENCY_FLAG_COUNT`, and the revenue multiple behind `MARKET_CAP_USD` / `LIQUIDITY_TIER`.
- **`_daily_seed` wrapper inlined per Plan 7.** Cumulus_Common's `seed_for` is Y-M-only (Plan 0 design choice). For daily cadence, Plan 7 and Plan 13 inline the same wrapper:
  ```python
  def _daily_seed(account_id, run_ts):
      day = _day_start(run_ts)
      return seed_for(f"{account_id}|{day.strftime('%Y%m%d')}", DATASET_SALT, day)
  ```
  Plan 7 and Plan 13 are the only two daily-cadence plans; no need to promote it to Cumulus_Common.
- **Audience SQL** is `SELECT DISTINCT * FROM DATA_JEDAIS.FINS__PUBLIC.V_ACCOUNT_ANCHORS WHERE ACCOUNT_TYPE_FLAG = 'BUSINESS'` — 11,529 business accounts on 2026-11-09. `_anchor_in_audience` re-checks the predicate in Python (defense in depth) and `_rows_for` raises `ValueError` for a non-BUSINESS anchor.
- The SP uses `cumulus_common.assert_coverage(session, COVERAGE_SQL, actual_sql)`: `COUNT(DISTINCT ACCOUNT_ID)` over the audience predicate must match `COUNT(DISTINCT ACCOUNT_ID)` over the whole table (every business anchor has at least one row somewhere).
- The MERGE replaces on `(ORG_ID, ACCOUNT_ID, PROFILE_DATE)` (its `ON`; the table PK is `RECORD_ID`). Re-runs on the same calendar day are idempotent (byte-identical). A later day INSERTs that day's rows, so **history accumulates**. Records go through `_merge` in 100,000-row batches (backfill safety).
- **Backfill:** `CALL SP_GENERATE_MOODYS_MARKET_CONTEXT(N)` writes the current day and the N−1 days before it for every *current* audience anchor. The task calls it with no argument (N = 1).
- The row factory tolerates up to `max(10, 1%)` failed (account, day) pairs; beyond that the run raises. Failures under the threshold are logged in `ERROR_MESSAGE` on a SUCCEEDED row.
- `accounts_processed` in `TASK_EXECUTION_LOG` is `len(audience)` (the business-account count). `ROWS_INSERTED` counts new rows only: the first run of a day equals the audience (1:1), a same-day re-run logs 0 (pure updates), and an N-day backfill logs the rows for days not yet written.

## Gotchas
- **Business-account audience only.** Person anchors are out of scope; don't read BIRTHDATE / ANNUAL_INCOME / CLIENT_CATEGORY. The audience is `ACCOUNT_TYPE_FLAG = 'BUSINESS'`, not a `CLIENT_CATEGORY` list.
- **Daily cadence.** `PROFILE_DATE` (DATE = `day_start.date()`), NOT `PROFILE_MONTH`. The seed bucket is the day start, so mid-day re-runs are byte-identical. `GENERATED_AT` and `LAST_DATA_REFRESH_AT` are both that day's midnight, not the wall-clock run time — query by `PROFILE_DATE` to find a run's rows.
- **Two salts.** `moodys` (daily) for market signals + `moodys_year` (year-stable) for editorial signals. Same shape as Plan 5 (`corelogic` + `corelogic_year`). Keep them separate so the daily RNG stream doesn't bleed into the year-stable one.
- **Year-stable subseeds.** `_year_seed` folds a suffix into the account id: `account_id + "_rating"`, `"_outlook"`, `"_outlook_changed"`, `"_rev_multiple"`, `"_52w_high"`, `"_52w_low"`, `"_flags"` — each its own `random.Random`, so adding a field never reshuffles another.
- **Hybrid year-stable + daily field model** like Plan 7. Editorial fields are year-stable; `DAILY_VOLATILITY_PCT` / `THIRTY_DAY_PRICE_CHANGE_PCT` are daily; `MARKET_CAP_USD` is hybrid. The year-stable cross-day test is **load-bearing** for this model.
- **`MARKET_CAP_USD` = `ANNUAL_REVENUE × revenue multiple × (1 + 30-day change / 100)`**, clamped to [$5M, $500B]. The multiple is a year-stable `uniform(3.0, 7.0)`. **Don't compute it from the daily salt** — the year-stable multiple is what keeps market cap plausible day to day.
- **52-week band and `LIQUIDITY_TIER` use the year-stable base** (`revenue × multiple`, no daily drift): high = base × `uniform(1.05, 1.50)` (floor base × 0.5), low = base × `uniform(0.55, 0.95)` (capped at high). Tiers: ≥ $50B Tier 1, ≥ $5B Tier 2, ≥ $500M Tier 3, else Illiquid. Don't tie them to the noisy daily market cap.
- **`_INDUSTRY_RATING_BIAS`** is an ordered list of 17 industry keywords (Banking, Finance, Insurance, Tech, Software, Healthcare, Energy, Oil, Mining, Utilities, Consumer, Retail, Industrial, Manufacturing, Construction, Real Estate, Transportation) matched by case-insensitive **substring**, first match wins. None / unknown → `_DEFAULT_RATING_BIAS` (Baa cluster). Reordering the list changes ratings for industries that match two keys.
- **`RATING_AGENCY_FLAG_COUNT`** is a year-stable draw in [0, 5], ~80% zero.
- **Snowflake digit-leading column rename.** Snowflake identifiers cannot begin with a digit, so the rowspec's `52_WEEK_HIGH_PRICE` / `52_WEEK_LOW_PRICE` / `30_DAY_PRICE_CHANGE_PCT` live as `FIFTY_TWO_WEEK_HIGH_USD` / `FIFTY_TWO_WEEK_LOW_USD` / `THIRTY_DAY_PRICE_CHANGE_PCT` (the `_USD` names came with the account re-scope — the band is a valuation, not a share price). DC fields are snake_case: `fifty_two_week_high_usd__c`, `fifty_two_week_low_usd__c`, `thirty_day_price_change_pct__c`.
- **0 BOOLEAN, 4 NULLable** (`OUTLOOK_LAST_CHANGED_DATE`, `ANNUAL_REVENUE_USD`, `EMPLOYEE_COUNT`, `ORG_ID`). No DC Boolean-declaration ceremony needed. The MERGE source SELECT must preserve `None → NULL`.
- **OUTLOOK_LAST_CHANGED_DATE NULL semantics.** Baseline: NULL when the outlook is Stable AND the year-stable draw is in the 80% never-changed bucket (~62% of rows before moves); non-Stable baselines get a date in the prior 12 months; other Stable baselines a 6–36-month-old date. Outlook moves then set it to the latest episode event on/before `PROFILE_DATE`.
- The `write_pandas(auto_create_table=True)` mis-types `datetime64[ns]` as `NUMBER(38,0)`. The MERGE source SELECT casts back via `TO_TIMESTAMP_NTZ(GENERATED_AT::NUMBER / 1000000000)` and `TO_TIMESTAMP_NTZ(LAST_DATA_REFRESH_AT::NUMBER / 1000000000)` — see template Task 4 §_merge.
- **Deploy under ACCOUNTADMIN.** The SP is `EXECUTE AS OWNER` and `write_pandas` creates a staging table, which needs CREATE TABLE on the schema. `python3 scripts/deploy_sp.py` runs `snow sql --role ACCOUNTADMIN -f …` by default, like Plaid's (`--role` overrides it). Recreating the SP as SYSADMIN fails every call with "Insufficient privileges … CREATE TABLE".
- 18 columns total (live): 14 NOT NULL (ACCOUNT_ID, PROFILE_DATE, CREDIT_RATING, RATING_OUTLOOK, MARKET_CAP_USD, DAILY_VOLATILITY_PCT, THIRTY_DAY_PRICE_CHANGE_PCT, FIFTY_TWO_WEEK_HIGH_USD, FIFTY_TWO_WEEK_LOW_USD, RATING_AGENCY_FLAG_COUNT, LIQUIDITY_TIER, LAST_DATA_REFRESH_AT, GENERATED_AT, RECORD_ID) + 4 NULLable (OUTLOOK_LAST_CHANGED_DATE, ANNUAL_REVENUE_USD, EMPLOYEE_COUNT, ORG_ID). `RECORD_ID` is a table default the generator never writes.
- **DC mapping (live).** DMO `BT_Moodys_Market_Context__dlm` with snake_case fields (`account_id__c`, `profile_date__c`, …). PK `record_id__c` (KQ `KQ_record_id__c`); `account_id__c` carries KQ `KQ_account_id__c` and the N:1 relationship to `ssot__Account__dlm.ssot__Id__c`. Not segmentable (`isSegmentable = false`).
- The DLO → DMO field mapping must be completed in DC Setup UI for fully-custom DMOs (the API endpoint returns 500). See the recipe at `../Snowflake_Claritas_Demographics/docs/dc-setup-recipe.md` from Plan 1 T7.
- Snowflake DATE columns auto-discover as `MM/dd/yyyy` in the DC data-stream POST body. Use that format for `PROFILE_DATE`'s and `OUTLOOK_LAST_CHANGED_DATE`'s `sourceFields` entries, NOT `yyyy-MM-dd`.
- DC mapping descriptions must be ≤521 chars (Plan 6 finding). Trim the DMO description if drafting against the rowspec verbatim.
- Cadence is **daily**: `USING CRON 15 3 * * * America/New_York` on `MAIN_WH_XS`, calling `SP_RETRY_WRAPPER('…SP_GENERATE_MOODYS_MARKET_CONTEXT()', 2)`. (The v2 schema header's `0 1 * * * UTC` is stale.)
- **Moody's apostrophe.** Directory and identifier names use `Moodys` / `MOODYS`; only human-facing text carries the apostrophe, doubled (`Moody''s`) inside the `$$` SP body and SQL comments.
- **Volume.** ~11.5K rows/day (11,529 on 2026-11-09), 1:1 with business accounts. History accumulates: 2,809,350 rows across 246 `PROFILE_DATE`s from 2026-03-01 to 2026-11-09 (a few dates in that span have no run).
- **Omega logical-key dedupe (2026-11-03).** The pre-QUALIFY duplicated `ssot__Account__dlm` anchor left 7 duplicate rows for Omega (`001am00000qvjs6AAA`), PROFILE_DATE 2026-09-26..10-02. Each pair had a populated-anchor copy (EMPLOYEE_COUNT 14800, Baa2) and a NULL-anchor copy (Baa3). We deleted the 7 NULL-anchor copies. The table then had 2,739,534 rows = `(ORG_ID, ACCOUNT_ID, PROFILE_DATE)` keys = RECORD_IDs. **Resolved 2026-11-03:** 15 non-duplicate Omega rows (10-03..11-02) still had NULL-anchor values left over from the pre-v1.4 non-deterministic `V_ACCOUNT_ANCHORS`. The audience already reads that view. The SP's one direct share read, `OWNER_BOOK_SQL`, now uses a deterministic QUALIFY: populated OwnerId first, then Account DSO, newest modified, then row hash. After the redeploy, `CALL …(32)` regenerated the window, and all 240 Omega rows now show EMPLOYEE_COUNT 14800 and revenue $24.5M. **Backfill side effect:** `CALL SP(N>1)` writes every *current* audience anchor for all N days, so it also inserts pre-history rows for accounts that joined the audience mid-window.
