# Commercial Atlas future production migration plan

This plan is preparatory. It does not authorize modifying/deploying the live ReactCommercial bundle or running CRM writes. The design checkpoint and source limitations are in `COMMERCIAL_BUILD_MILESTONE.md`, `COMMERCIAL_SOURCE_CONTRACT.md`, `COMMERCIAL_MIGRATION_CONTRACT.md` and `COMMERCIAL_PRODUCTION_ACCEPTANCE.md` under the November 12 design-study directory.

1. **Decisions before implementation.** Confirm production scope/branch and current org. Resolve the delinquency-predictor meaning with the source-model owner, replace or explicitly relabel rank-derived health/drop, decide the empty-book fallback policy and model-EV-versus-proposed-amount default. Define signed-in actor versus View As ownership for ordinary writes and cross-sell separately. Approve secure draft/note persistence and exact route restoration.
2. **Protect plumbing.** Inventory current routes/SDK/bridges/ACC/config/theme code and establish passing Retail/Wealth/Commercial regression baselines. Keep SalesforceDotCom reads on GraphQL and external/provider reads on Data 360. Add tests for GraphQL errors in HTTP 200, FLS omissions, scope/caps, successful empty and unavailable sources.
3. **Exact company/product/deal foundation.** Port source-backed selectors and a company workspace state model without importing fixture data. Keep product action code and source Opportunity ID in every preparation/proposal. Test duplicate names, multiple deals, Account reassignment, Back/reload and shared shell search.
4. **Today and credit.** Port the compact hero, native driver explanation, exact-ID blended work, due/snooze states, business net flow and real CRM history. Implement independent payment/credit aggregates with native source periods and verifiable company cohorts. Do not invent a health score or history for missing profiles.
5. **Company intelligence.** Wire native Demandbase/Harmonic/UserGems/Moody's/BoardEx/MSCI/Gong/AML/marketing/external-service sources and per-company ZoomInfo/BoardEx/MSCI/SEC dossier. Verify no-match, populated and error states where source data actually exists. Preserve source/current/new-employer identities and external reference boundaries.
6. **Treasury and origination.** Preserve current twelve-row grid/holder/mover/history/outcome contracts, owned/existing-opportunity guards and source names. Implement CRM Leads, warm intros and owner-Wealth handoffs with reviewed recipient/identity/consent and active metadata values. Keep unsupported Phone/Industry/notes as local context unless bridge work is separately approved.
7. **Company execution.** Connect current Task/Event/Goal/LifeEvent clients with the exact supported create/update/delete field matrix. Preserve actual source assignee/Who/What, original Event duration on updates, date-only goals and verified FinancialPlan ownership. Keep personal records in a mixed commercial book separate from company planning. Do not add existing Case/Opportunity updates implicitly.
8. **Write lifecycle.** Add permission/ID/recipient validation, double-submit prevention, definite failure/no-refetch and ambiguous timeout recovery. Only confirmed success marks executed/refetches. Verify the refreshed record and source aggregates instead of incrementing a local source metric.
9. **Shell, AI and settings.** Retain full multi-object search/waffle/notifications/Tasks/avatar/setup/View As contracts, authenticated ACC agent teardown/re-embed and actual record grounding, supported prompt slots, AI action config/model catalog, org theme library and per-user activation/display size. Do not replace them with prototype simulations.
10. **Acceptance and release.** Execute every production gate, four-width/keyboard/permission/empty/error/retry scenarios and Retail/Wealth regressions. Independently review exact source continuity and live write evidence. Only then prepare an explicit deployment package/runbook for user review; deployment requires the separately authorized production scope.

Each implementation checkpoint should record actual source scope, tests, remaining source defects and exact committed paths. Do not stage prototype captures into a production bundle or describe local mock coverage as deployed parity.
