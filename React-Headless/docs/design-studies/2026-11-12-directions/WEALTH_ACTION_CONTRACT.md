# Wealth Atlas action contract

November 13, 2026. **The standalone mock only saves local proposals.** No handler below is called by the mock. Production must review these mappings against the exact migration commit, perform permission checks and return verified receipts before marking any action executed.

| Designed action | Existing implementation floor | Required runtime behavior |
|---|---|---|
| Review household / source / product | Wealth customer fetchers; shared GraphQL/Data Cloud clients and whitespace source | Carry stable org, actor, effective owner, exact Account, product/source key, source period and safe return context. Source selection must not depend on display name. Unauthorized/unavailable is distinct from empty. |
| Prepare call / review folio | Wealth TearsheetBuilder, shared Prep/Why/AiResult modals and AI clients | Keep recorded facts separate from editable preparation and composed/model text. Include only authorized exact-customer sections. Model failure never erases source evidence; no generated/sent/exported claim without its actual result. |
| New Task | `crmWriteClient`→`CrmWriteRest` task | Subject, description, priority, status, due date, WhoId and WhatId. Ordinary creates default to the authenticated actor, not merely the viewed advisor. Resolve a Contact/Lead for WhoId; an Account is not a WhoId. |
| Source Task edit / complete / delete | task update/delete routes | Immutable target Task ID; supported subject/status/priority/dueDate/type/description/WhatId/OwnerId updates. WhoId remains fixed. Completion is an explicit Status=Completed update, not deleting the row locally. Refetch only after a verified matching receipt. |
| Propose review meeting | event create route; ScheduleModal | Provider review date is preparation, never a booking. Create supports subject/description/start/duration/WhoId/WhatId. Preserve local time zone and reviewed UTC conversion. Current create ignores the richer owner/type/location/ShowAs planning fields; either implement them explicitly with tests or label/omit them for live execution. |
| Source Event edit / cancellation | event update/delete routes | Immutable Event target; supported subject/start/type/description/location/ShowAs/WhatId/OwnerId. WhoId and duration are fixed in the current update contract. Delete only the reviewed target after explicit confirmation/receipt. Source Event operation proposals never become new meeting drafts. |
| New / edit FinancialGoal | goal create/update; CustomerGoalModal | Name/type/status/priority/description/date/target/actual and exact CRM FinancialPlan. New goal requires a plan whose Account is verified; a provider-only Draft is not that CRM record. Existing goal plan is fixed. Zero is a real amount; current blank-string updates mean leave unchanged, not clear. |
| New / edit Life event | life-event create/update; LifeEventModal | Create uses exact Contact/type/date/name. Update changes only name/date; Contact and type stay fixed. Preserve UTC date-only semantics and avoid name-based Contact inference. |
| New / edit Lead | Lead create/update | First/last/company/status/source/email/AnnualRevenue; preserve currently selected legacy picklist values. AnnualRevenue is annual company revenue. Graph target/referrer remain separate source IDs and do not imply an existing Lead or consent. |
| Product Opportunity | `createWhitespaceOpportunity` / opportunity create route | Exact Account+product, LeadSource=Cross-sell grid, Prospecting and reviewed close-date defaults. Known-owned/existing grid opportunities suppress duplicate proposals. Current native helper seeds Amount from modeled EV; Atlas requires explicit banker review instead. Cross-sell explicitly assigns the effective viewed owner in the current helper, unlike ordinary create defaults. Do not add unsupported generic Opportunity update/delete. |
| Source inflow / career / marketing / risk outreach | native source feeds and the Task/preparation paths above | Retain source key/date/Account/reference. Screening case references are not CRM Case IDs. Inflow/career signals do not establish available proceeds; clicks/opens are not conversion or permission. No trade execution or compliance disposition is implied. |
| Email outreach | Email modal / email bridge | Resolve and review the exact recipient and body, enforce backend permission, inspect actual send results and ambiguous failures. Current Apex send path does not inspect every send result; fix before showing Sent. Suppress duplicate submissions; a timeout cannot trigger blind resend. |
| Case creation | Case modal / case create route | Review Account/subject/priority/description and the actual supported fields. No source-case update/resolution operation is invented from the read-only case cards. |
| Private draft / folio / pin | Current browser state plus migration private-state adapter | Namespace by stable org+actor+effective read owner+persona+Account+record/source key as appropriate. Warn on failed storage, quarantine/discard old mock drafts, invalidate mismatched provenance after reassignment, and never automatically replay proposals. |

All writes need object/type validation, CRUD/FLS/sharing policy, supported-field validation, one in-flight submission, durable success/uncertain/error state, safe retry/reconciliation and independent refetch failure handling. HTTP200 alone is not success. A response ID must match the requested original record for update/delete and the expected object type for inserts. Models, owner preview and hidden controls do not confer authorization.
