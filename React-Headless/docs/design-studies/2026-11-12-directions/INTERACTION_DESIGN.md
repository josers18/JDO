# Atlas and Panorama: visual working tools

The user likes Atlas and Panorama, with Atlas cleaner, but finds the full mock too much text in boxes. This pass keeps their visual identity and readable scale while making data selection and investigation more direct. Focus remains available.

## Additions

- A real relationship map: advisor-to-account connections, selectable nodes, contextual evidence, lenses for signals/milestones/goals, full directory, and an up-to-three-account comparison tray. Distances and spokes are navigation, not financial measures or inferred relationships between clients.
- A deal landscape: plot recorded opportunity value against recorded close date, select a deal, switch scale, and explore a local planning board. Dragging a deal or choosing a stage previews a scenario. It never changes the captured aggregate or Salesforce record. A deliberate save keeps an action draft.
- A milestone calendar: browse years and event families, select a dated marker, inspect the source record and prepare outreach. Use a horizontally scrollable timeline on small screens, not compressed labels.
- A balance composition graphic: aggregate captured account balances by their recorded type, select a segment, and filter the financial-account table. Label this recorded balances, not AUM or net worth; loans may be included and missing balances are excluded.
- Source-backed visual summaries for the home view and goal funding. Use actual captured proportions and counts, not decorative charts or invented change statistics.

## Visual system

Retain the existing cobalt/white Panorama and lavender/iris Atlas tokens, native system type, 17–20px body text, and 15–16px metadata. Put visual interaction on open canvases, keep supporting controls quieter, and reserve outlines/active rings for selection. Native buttons, keyboard alternatives to drag, source context, empty states, and reduced-motion support are required.

## Data boundaries and review

Reuse existing CRM/Data Cloud captures only. Every plotted dot, timeline marker, balance segment, and goal ring must resolve back to captured records. Comparison counts refer to the sample. Local scenarios stay visibly distinct from captured facts. Verify the new linked interactions at desktop/tablet/mobile widths and rerun the existing action/dossier journeys.
