## Preserve what already works

- Today’s household review focus and provider-date versus booked-meeting distinction; six selected review examples, outside-platform conversations and Julie’s selected executions.
- Wealth Growth’s household capital-path composition, scored product choices and actual captured monthly score scrubber. Keep outside assets separate from CRM holdings and expected-value uplift separate from opportunity amount.
- Intelligence’s plan/concentration/liquidity lenses and Review horizon’s review/outside-platform modes, while replacing identity-by-name and singleton assumptions with source-keyed selection.
- Julie’s financial-account records, property owner gate, transactions/trade ledger, native financial-plan goals, interaction history, campaigns, notes, screening, packet selection and preparation. A second customer must receive its own evidence or an honest unavailable state.
- Pipeline stages, searchable captured deals, exact Account drill-in, persona-specific Workbench review studio and local preparation. Keep the Atlas readable type scale and interactive visual presence; avoid long horizontal household ribbons as the only access method.

## Source constraints to carry into implementation

1. Held-away **home opportunity** uses positive active Brokerage/Robo-Advisor assets; the customer summary’s held-away query is broader active `Balance_Category='asset'`. Those are different slices, not a discrepancy to hide by summing them. Concentration AUM is holdings-source market value; positive financial-account balances can include lending and are not an equivalent AUM denominator.
2. Native plan totals/dates and CRM FinancialGoal records are separate sources. Goals link through FinancialPlan.AccountId; a provider review date is not an Event. Stale-plan status and “not updated in 12 months” follow the source rule.
3. Native source helpers may return org scope when the book is empty. The new Wealth mock must retain returned scope and represent an empty/unavailable banker book honestly. Production fallback policy is a migration decision, not a design-only edit.
4. Grid outcomes identify open opportunities by Account plus native product-name prefix, an inherited heuristic. The current grid path submits modeled EV as Amount; the newer Retail mock asks the banker to review amount. Decide and label the Wealth proposal behavior explicitly; neither EV nor a draft is booked revenue.
5. Cross-sell creates can pass the View As owner, while other bridge operations have different assignment behavior. View As display scope, record authorization and assignment are not interchangeable. ACC’s `contextLabel` changes chrome text; it does not automatically ground a running conversation.
6. Source historical claims/comments and deployed behavior need fresh validation before live rollout. This audit does not convert prior session counts or successful local rendering into current org evidence.

## Recommended sequence and acceptance gate

Start with exact-customer/product continuity and source boundaries (W05/W09/W12), then advisor prioritization and plan reviews (W01/W02), capital/exposure and acquisition (W03–W06), Intelligence/trading (W07/W08), and execution/folio depth (W10/W11). Shell/runtime preservation and a final capability re-audit close the design plan (W12–W14). W15 remains optional source discovery.

Each milestone must produce a browser-reviewable Wealth view, bounded actual-source fixtures or honest unavailable states, exact-ID selector tests and a record-level action/return journey. Run prior Retail suites as isolation regressions when common study plumbing changes. Production implementation/deployment remains a subsequent plan and authorization.
