# Atlas shell preservation audit

November 13, 2026. Read-only source inspection and bounded read captures for the shared Atlas shell across Retail, Wealth and Commercial. Retail page-content work remains held. This is a source contract and acceptance map, not authenticated production acceptance. No production source, backend, metadata, permission assignments or org records were changed by this audit.

The current apps use the same shared shell components. Their production entry points are `ReactRetail/src/shell/AppShell.tsx`, `ReactWealth/src/shell/AppShell.tsx` and `ReactCommercial/src/shell/AppShell.tsx`, under `force-app/main/default/uiBundles/`. Each mounts App Launcher, multi-object Global Search, Notification Bell and User Menu. Home layouts additionally provide View As and Current/Cockpit controls. The customer route suppresses the shell chat when mounting its own record-context chat to avoid two ACC embeds.

## Permissions and assignment boundaries

- Current AppLauncher catalog and Setup/Data Cloud Setup links have no client-side permission filter. Showing a tile does not grant access; native Salesforce authorization remains authoritative. The “Open in Salesforce” destination offers the permission-aware full catalog.
- Persona Access permission sets grant app visibility, launcher Visualforce-page access and tab visibility. They are not comprehensive CRM/Data Cloud or admin permission grants.
- `CommandCenterConfigAdmin` grants CRUD/view-all/modify-all on CommandCenterConfig__c and FLS to center config, model cache, theme library, active-theme and display-size fields. Current Config/UserMenu source does not use a custom permission to hide all admin controls. An audit of those links is not proof every user may successfully change config.
- `CrmWriteRest` and `CommandCenterConfigRest` are declared `with sharing`; this is not proof of per-operation CRUD/FLS enforcement. Production authorization acceptance remains pending. This mock scope makes no backend/security-policy changes.
- `CrmWriteRest.whoami` returns actual UserInfo user/name/orgName, not orgId. Customer/owner/view selection cannot redefine the session actor or tenant identity.
- Task/Event/Case/Lead creates do not generally accept a new owner in their create handlers; server/session defaults apply. Opportunity create explicitly assigns ownerId when provided, and the cross-sell grid supplies the effective banker. Task/Event updates permit explicit owner changes. Local mock proposal metadata is not evidence of a committed assignment.
- Global Search/Bell read the authenticated sharing-visible records without the home View As owner filter. A redesigned mock should state source scope rather than falsely imply all chrome follows the previewed book.
